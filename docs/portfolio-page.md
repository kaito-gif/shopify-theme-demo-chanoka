## デモストアで実装したもの

ベースは Shopify 公式テーマ **Dawn 15.5.0** です。素の Dawn には無いものを
足していますので、**Dawn との差分がそのまま手を動かした範囲**になります。

追加・変更したのは Liquid セクション3本・CSS 4本・JS 1本と、
テーマ設定まわりの改変で、およそ 1,300 行です。

### 1. 商品比較表セクション

最大4商品を並べて価格・内容量・産地・味わいなどを比較できる表です。

- マークアップは `<table>`。見出しセルに `scope="col"` / `scope="row"` を付け、
  スクリーンリーダーがセルと見出しの対応を読み上げられるようにしています
- 表そのものには `<caption>` を用意（視覚的には非表示）
- 横に長くなるため、1列目のラベルを `position: sticky` で固定
- 横スクロール領域に `role="region"` と `tabindex="0"` を与え、
  マウスを使わずキーボードだけでもスクロールできるようにしています
- 比較する商品・行の項目はテーマエディタから設定できます

### 2. 淹れ方の手順カルーセル

スクロールスナップで1ステップずつ送れる横スクロールUIです。

- ネイティブのスクロールに `scroll-snap-type` を重ねた実装。
  重いスライダーライブラリは入れていません
- 前後の送りボタンつき。ボタンには `aria-label` を付与
- `prefers-reduced-motion: reduce` の環境ではアニメーションを止めます
- 各ステップの画像は、色味が揃うよう1枚の基準画像から派生させて生成しています

### 3. FAQ セクション（構造化データ付き）

`<details>` / `<summary>` によるアコーディオンに加えて、
**FAQPage の JSON-LD を出力**します。Dawn 標準の「折りたたみ式コンテンツ」は
構造化データを出さないため、そこを補うセクションです。

- 質問・回答が空のブロックは JSON-LD から除外（必須プロパティを満たさないため）
- 1ページに FAQPage は1つだけという制約があるので、
  出力のオン・オフをテーマエディタから切り替えられるようにしています
- Schema Markup Validator（validator.schema.org）で **エラー0件・警告0件**

> 補足として、Google は2026年5月にFAQリッチリザルトの表示を全サイトで終了し、
> 6月にはリッチリザルトテストからも対応を外しました。検索結果に
> アコーディオンが出ることはもうありません。ただし FAQPage は schema.org の
> 有効な型のままで、Google もページの理解には引き続き使うと明言しているため、
> マークアップは残し、検証は schema.org のバリデータで行っています。

### 4. SNS共有画像のフォールバック

管理画面でソーシャル共有画像が未設定のページでも `og:image` が空にならないよう、
テーマ設定に既定画像の項目を追加し、`meta-tags.liquid` から参照しています。
管理画面側で個別に指定されていれば、そちらが優先されます。

### 5. フッターの注記

デモである旨・架空ブランドである旨・画像がAI生成である旨を、
テーマ設定から編集できる形で全ページの最下部に出しています。

### 商品データの登録

6商品を Admin API から登録しました。手作業ではなくスクリプトにしてあるので、
商品数が増えても同じ手順で流せます。

## 作業の進め方

コードを書き換えたあと、「動いているはず」で完了報告はしません。
毎回この順で確認してからお渡しします。

1. `shopify theme check` を通す（エラー0件）
2. ローカルでレンダリングし、Liquid のエラーが出ていないことを確認
3. **実ブラウザで実際に操作する。** 構文チェックでは表示崩れを検出できません。
   このデモでも、崩れの2件はブラウザで触って初めて見つかりました
4. コンソールエラーが0件であること
5. **テーマエディタから設定を変更しても壊れないこと。**
   納品後に触るのは運用担当の方なので、ここまで確認して初めて完了とみなします

スマートフォン表示は、PC のブラウザ幅を狭めるだけでは足りない場合があります
（macOS の Chrome はウィンドウ幅を500px未満にできません）。
デバイスモードか実機で確認します。

## つまずきやすい箇所と、その対処

実装中に実際に踏んだもののうち、原因が分かりにくかったものを挙げます。

**テーマを反映したら、管理画面で設定したはずの内容が元に戻っていた**

ローカルからテーマを push すると、テーマエディタ側で加えた設定
（`settings_data.json` や各テンプレートの JSON）が上書きされます。
エディタで設定を変えたら、push の前に必ず pull で取り込みます。

**管理画面では有効なのに、ストアフロントで商品ページが 404 になる**

商品のステータスが「有効」であることと、「オンラインストアに公開されている」ことは
別です。API から作成した商品は販売チャネルに自動追加されないため、
公開先を明示的に指定する必要があります。

**商品URLが日本語のまま生成され、リンクが長大なエンコード文字列になる**

Shopify が自動生成するハンドルは商品名から作られるため、日本語名の商品では
日本語のままになります。登録後にローマ字へ振り直します。

**横スクロールUIの送りボタンが効かない、あるいは先頭に巻き戻される**

`scroll-snap-type: x mandatory` を使っていると、幅の構成によっては到達可能な
スナップ位置が先頭しか無くなることがあります。加えて Chrome は、
スムーススクロールでの相対移動を現在のスナップ位置へ戻してしまいます。
最後の項目のスナップ位置を調整したうえで、JS 側は移動先を絶対値で指定します。

**ページ全体に意図しない横スクロールが出る。狭い画面ほど顕著**

横スクロール領域の中で `position: absolute` を使った要素が、
包含ブロックの指定漏れでコンテナのクリップを抜けているケースがあります。
視覚的に非表示にするためのユーティリティクラスが原因になることが多いです。
子要素を1つずつ非表示にして切り分けるのが最短でした。

**ブラウザ上でCSSを差し替えて検証しているのに、何も変わらない**

セクション単位のCSSは `<head>` ではなく body 内に読み込まれることがあります。
`<head>` にスタイルを差しても後勝ちで負けます。効いたかどうかは見た目ではなく
`getComputedStyle` の実値で確認します。

いずれも「症状からは原因が想像しにくい」類のものです。
同じような症状でお困りでしたら、調査からお手伝いできます。
