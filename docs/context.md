## このリポジトリの位置づけ

副業案件の獲得に使うポートフォリオ用デモストア。クライアント案件ではない。
掲載できる実績が現時点で無いため、自作のデモストアで実力を示す構成にしている。

素のDawn 15.5.0が初期コミット（`25f15eb`）なので、**そこからの差分がそのまま
「手を動かした範囲」の証明**になる。この性質を壊さないこと。

ブランド `chanoka`（茶の香）は架空の日本茶D2C。実在企業ではない。
商品画像はすべてOpenAIの画像生成モデルによるAI生成物。

計測条件: モバイル / シークレットウィンドウ / 拡張機能なし /
`https://chanoka-demo.myshopify.com/`

| カテゴリ | スコア |
|---|---|
| パフォーマンス | 98 |
| ユーザー補助 | 100 |
| おすすめの方法 | 100 |
| SEO | 100 |

LCP 1.8秒 / FCP 1.8秒 / TBT 0ms / CLS 0 / Speed Index 1.8秒 / TTI 1.8秒 /
サーバー応答 70ms。

**この数値をポートフォリオに載せる。** 計測条件を満たさないと再現しない
（条件の詳細と踏んだ失敗は `CLAUDE.md` の「ハマったところ」にある）。

Search & Discovery を導入したため測り直した値。導入前は パフォーマンス99 /
サーバー応答20ms で、それ以外の指標は同じだった。減点の内訳にアプリ由来のものは
無く（「使用していないJavaScript」33KiBは Shopify が全ストアへ配信する
Web Pixels Manager）、LCP・TBT・CLS も動いていない。1点差とサーバー応答の差は
CDNのキャッシュ状態による計測ごとのばらつきの範囲。**下がった原因を調べ直す
必要はない。**

ユーザー補助100は `animations_reveal_on_scroll` をオフにして得た値。オンだと
Dawnのスクロール表示アニメーションで要素が透明な最中にaxeが色を測り、
`color-contrast` が27件失格する（実際の文字色は `#121212` で実害はない）。
演出よりスコアを取る判断を済ませている。

## ストアの構成（2026-08-02 整備）

コレクションはストア作成時に自動生成された `frontpage`（Home page）しか無く、
メニューの遷移先が `/collections/all` になっていた。疑似コレクションは説明文・
画像・SEO・手動の並び順を持てないため、`templates/collection.json` の
「コレクションの説明を表示」などが空回りしていた。以下を整えて解消した。

| 項目 | 内容 |
|---|---|
| `tea`（茶葉一覧） | 手動コレクション。6商品を手動の並び順で。説明文とSEOあり。メニュー「茶葉一覧」とトップの「人気の茶葉」の参照先 |
| `low-caffeine`（カフェイン控えめ） | 自動コレクション。タグ `caffeine-low` が条件。価格の安い順 |
| 商品タグ | カフェイン量から `caffeine-low` / `-medium` / `-high` を機械的に付与 |
| `frontpage` | 削除 |
| Search & Discovery | 導入済み。絞り込みの名称を `Availability` / `Price` から「在庫状況」「価格」へ |
| フッター | `link_list` ブロックを1つ置き、Footer menu（茶葉一覧・カフェイン控えめ・お問い合わせ）を表示 |

作成は `scripts/seed-collections.py`。何度流しても同じ結果になる。

産地・味わい・カフェインは商品説明のHTMLに `<li>` で埋めているだけでタグにも
メタフィールドにもなっていない。**これらで絞り込ませたい場合はメタフィールド化が要る。**
タグでも出せるが、タグはローマ字なので画面にそのまま `caffeine-low` と出てしまう。

### トラブル対応事例を書くときの制約

このページで最も効く節になる見込みだが、同時に最も情報漏れのリスクが高い。

- 判断基準は「**技術記事に書いても違和感がない粒度か**」。満たせば個別案件の
  記述ではなく一般的な知見として成立する
- クライアント名・ストア名・ドメインに加え、**業種・規模・時期も書かない**
  （組み合わせから特定されうる）
- 「〇〇なサイトで」ではなく「**〇〇という事象が起きたときは**」と書く
- 安全な例: 「本番反映後に旧デザインが表示される → configキャッシュ残存」
- 注意が必要な例: 移行や公開の文脈を1語でも足すと特定に近づくものは、
  **事象と対処だけで止める**

### 経験年数の書き方（2026-08-02 決定）

**「Web開発の実務は2年」と書き、Shopify の年数は書かない。**

雇用されての Web 実務が途切れず続いている起点と、副業の初受注の起点の
どちらで数えても「2年」で破綻しない。職務経歴書の起点とも一致するので、
問い合わせ時の口頭説明とずれない。

Shopify を年数で出さないのは、実務として数えられる期間が短く、書くと
マイナスに働くため。デモストアの実装解説と Lighthouse のスコアで示す。

**根拠の数字（在籍期間・勤務先が特定できる情報）はここにも書かない。**
公開リポジトリのため。手元で確認する場合は職務経歴書と請求書の日付を見る。

**勤務先の社名も公開ページに書かない。** 現職は受託でクライアント案件を
扱うため、社名を出すと「つまずきやすい箇所」の事例と結びついて案件が
特定される経路ができる。「Web制作会社に所属」までに留める。

## 構造化データの検証（2026-08-02）

`sections/faq-structured.liquid` が出力する FAQPage JSON-LD を
**Schema Markup Validator（`validator.schema.org`）** で検証し、
エラー0件 / 警告0件。FAQPage 1件・Question 4件、各 Question に
`acceptedAnswer > Answer > text` が揃っている。

**リッチリザルトテストは使えない。** GoogleはFAQリッチリザルトを2026-05-07に
全サイトで廃止し、2026-06にリッチリザルトテストとSearch Consoleの
FAQレポートからも対応を外した（Search Console API は2026-08で終了）。
FAQPage 自体は schema.org の有効な型のままで、Googleはページ理解のために
引き続き解析すると明言しているため、マークアップは残す。
検証はリッチリザルトテストではなく `validator.schema.org` で行うこと。

ポートフォリオでの書き方に注意。「FAQリッチリザルトが出る」とは**書けない**。
「構造化データを正しく出力できる／Dawn標準では出ないものを補える」という
実装能力の証明として提示する。
